# 分层备份与恢复方案（草案）

状态：设计要求，尚非已实现能力。与 [升级方案](upgrade-entry-design.md) 配套；本方案描述平台完整的保护模型，不扩大首版升级入口的支持范围。首版仍只开放经过验收的应用升级；基础服务升级、存储迁移、K3s 升级/配置迁移分别立项。

## 1. 从恢复目标生成备份范围

备份以数据归属和恢复依赖为依据，不按 Pod 数或组件目录打包。每次操作生成保护计划：操作类型、来源/目标版本、影响范围、数据与配置清单、共享依赖、允许丢失的数据窗口（RPO）、恢复时限目标（RTO）、停机预算、所需空间、执行责任人及已知缺口。

发布包仅包含通用组件数据契约、固定工具及格式、版本迁移规则和支持证据；**打包不输入或探测已部署集群的信息**。现场根据实际安装组件、逐组件版本/schema、数据位置和本次意图生成具体保护计划。备份容量、落点、密钥引用、资源名称、冻结对象和 backupId 均属于现场状态，不能写入可复用发布包。独立备份也复用这些契约，不要求存在目标升级版本。

采用“通用编排 + 组件适配器 + 版本迁移规则 + 单次现场计划”。包内有组件不表示现场已安装；未安装组件不生成数据备份项，未知状态则阻断。未升级组件若被迁移影响或是必要恢复依赖，仍须纳入保护。共享 PG/S3 按实际数据归属和消费者计算范围，不能把包内组件目录直接当成备份清单。唯一数据、可验证重建内容和外部负责方分别列明；缺少覆盖须阻断对应操作。

| 操作类型 | 最低保护范围 | 恢复验收重点 |
|---|---|---|
| 应用升级：Apeiron、Limani 等 | 该应用的数据库/角色、对象/文件、专属卷、原始密钥、配置及旧制品；包含被迁移的共享状态 | 旧程序与旧 schema/密钥匹配；身份、权限、文件引用和真实业务可用 |
| 基础服务升级：PG、S3、Git 等 | 服务完整状态、格式/版本、配置与密钥，以及受影响消费者的一致性恢复点 | 全部受影响消费者验证；不能只证明基础服务端口已开 |
| 存储迁移：存储类、驱动、访问模式、后端变更 | 所有待迁移卷数据、PV/PVC 映射、拓扑、快照/备份、应用一致性及原卷保留方案 | 新存储真实读写、重启/重调度、权限/性能及切换后回退条件 |
| 集群变更：节点扩容、K3s 升级、配置/网络/datastore 迁移 | 控制平面状态、server token、节点配置及受影响的卷/应用恢复方案；扩容记录节点准入与前后基线 | API、DNS、CNI、CSI、身份、镜像拉取和业务链路；按实际影响确定业务数据保护范围，整集群恢复须另行验收 |

同一不可分割阶段若跨多类，取影响范围并集并形成一致恢复点；可分离时拆成独立阶段，各自生成恢复点和提交基线，避免同时改变集群、存储和业务 schema。不能要求整个复合变更始终共用一个初始恢复点。修改声明不等于迁移数据，恢复控制平面也不等于恢复业务卷。

共享服务须明确恢复粒度。例如 PG 全量备份可只做一次，但单应用恢复不能直接回放全量 dump，覆盖同实例其他应用。若无法隔离恢复，需要把全部消费者纳入停机、数据丢失说明与验收；无法接受则拒绝该变更。

### 1.1 多集群与扩容阶段

完全独立的内网 multi-k3s 和外网 single-k3s 各自识别来源、组件、配置与数据，生成独立计划和备份集，不要求相同来源或目标版本。备份索引按集群/安装身份、操作/阶段和 backupId 隔离；可共用备份设施，但必须验证访问隔离和声明的故障域独立性，恢复不允许凭同一发布版本选择另一个集群的数据。若发现共享服务或同步链路，须重新计算消费者及一致性边界，不能继续假设独立。

内网现有 3 server、拟新增 5 agent：扩容前按影响范围保护控制平面、token/配置及必要业务数据，扩容能力验收后提交新的节点/存储访问基线，再为应用升级生成新鲜一致性备份。扩容前的控制平面快照不能替代扩容后的业务恢复点；应用失败默认保留已验收节点，不能自动恢复旧 datastore 撤销扩容。扩容失败的清理必须核查是否已有工作负载或唯一数据落在新节点，不能直接删节点/卷。

外网 single-k3s 独立计算停机与恢复资源；内网需验证断网取回、旧制品及工具可用，不能借用外网联网恢复结果。节点数增加不自动迁移 local-path 数据或解除 RWO 限制，也不自动扩大备份范围到所有缓存；范围由实际数据和恢复目标决定。

## 2. 数据与配置清单

下表为应建立的契约，不代表现有脚本已全部覆盖。每个安装根据实际启用组件列出具体资源和负责方。

| 层次/组件 | 必须保留的状态 | 可重建或需另行判断的部分 |
|---|---|---|
| 主机与集群外环境 | inventory、节点角色、磁盘/挂载关系、网络、防火墙、systemd/启动配置、外部 DNS/LB/存储/数据库接入信息和必要凭据 | OS 和软件包可用固定离线制品重装；业务 hostPath、local-path 卷不能遗漏 |
| K3s 控制平面 | 按 SQLite/内嵌 etcd/外部数据库选择正确备份；匹配的 server token；K3s 配置及 drop-in、实际启动参数、datastore TLS/加密相关恢复材料、版本、注册表信任和认证 | 二进制可离线重装；datastore 中的 PV/PVC、Secret、CRD 等对象记录不包含业务卷文件；只导出 YAML 不等于控制平面备份 |
| 持久存储与驱动 | 业务卷内容、PV/PVC/volumeHandle 与应用对应关系、StorageClass/CSI 版本和参数、节点/可用区约束、访问模式、reclaim policy、容量、加密密钥 | 副本是可用性机制；源后端上的快照不是独立灾备副本；可重建空卷不必复制 |
| PostgreSQL | 数据、角色/授权、扩展及版本、配置、恢复所需密钥；选择逻辑备份或经验证的物理备份/WAL 方案，明确恢复粒度 | 数据目录不能在运行中随意复制；PITR 必须有完整有效的基础备份/WAL 链，首版无此能力时如实说明 |
| S3/SeaweedFS | 业务对象及需要保留的版本/元数据、桶配置/策略/身份；原生恢复还需匹配的 filer 元数据、volume 数据及必要集群状态 | S3 导出与原生卷恢复是不同方案；不能只备份 volume 或只备份 filer；多副本不保护误删/错误迁移 |
| Git/Forgejo 与 CI | PG 数据库、仓库对象/refs、LFS、附件、配置及密钥；Woodpecker 等组件的独立数据库/SQLite、必要任务状态和凭据 | 仓库镜像或 Git clone 未必包含 LFS/附件/应用数据库；构建缓存可重建，制品按业务保留要求判断 |
| 身份与证书 | Keycloak 原数据库与用户身份、角色/客户端关联；应用加密密钥、服务端/客户端匹配凭据、CA 私钥及证书、签名材料 | 可以按既有 CA 重签的叶证书可重签；原始身份和应用解密密钥不能用新生成值替代 |
| Nexus/制品服务 | 数据库/配置、blob 内容、密钥和权限之间的匹配状态；必要镜像/Chart/工具的固定摘要与可独立读取的副本 | 有完整可信离线副本的不可变制品可引用复用；代理缓存只有确认可再次离线取得才可排除 |
| Apeiron | 共享 PG、业务 S3、System Skills Git、应用 Secret；逐项确认工作台持久文件、用户未提交内容及其真实落盘位置 | 临时容器/进程可重建；不能把工作台整个目录都当缓存，用户唯一文件须保护 |
| Limani（当前 ontology 部署） | ontology 数据库/角色、原始加密密钥、数据库身份及 OIDC 配置/Secret，与来源版本配套 | 应用镜像可重建；恢复时重新生成加密密钥可能导致旧数据不可读 |
| 队列、任务、搜索/向量服务 | 唯一保存的待处理消息、任务/幂等记录、向量和元数据，或声明可重建的权威来源与流程 | 有完整权威源且重建耗时满足 RTO 的派生索引可排除；不能默认所有队列和向量都可丢 |
| 日志与审计 | 按业务追溯、运维诊断与保留要求确定范围，保留恢复操作审计 | 普通临时日志可按规则排除；安全/业务审计不能仅因“不影响启动”而丢弃 |

### 2.1 现有明确缺口

以下是升级方案所引用评审基线的已知缺口，不是对所有后续版本的能力结论；实现时须固定源码/制品并逐项重新核验，只有恢复证据通过才能更新能力声明。

- 当前 Git 脚本不覆盖仓库 PVC；PG 备份只保护其数据库。Git/CI 文件状态有现存非目标，不得擅自将规格改为“已支持”。涉及这些状态的升级在能力补齐、规格确认及真实恢复验收前不开放。
- SeaweedFS 当前依赖副本、没有完整灾备恢复流程。它既承载业务对象又可能承载备份，必须补齐外部副本与恢复适配器；不能自备份到自身后声称整个平台可恢复。
- CA 私钥不在常规 Secret 导出中，须通过独立加密保管流程覆盖；各组件脚本的告警、无数据输出和退出 0 不代表覆盖完整。
- Apeiron 的 System Skills 备份脚本会触发 Job；任务受理不等于 Job 完成或备份已验证，接入时须等待并校验实际产物。

### 2.2 排除规则

排除项必须列出资源、理由、权威来源、重建版本/方法、耗时及证据。通常可排除可重建的 Pod、临时文件、缓存，以及已有独立离线副本的不可变制品。副本、未验收恢复流程、旧规格中的非目标都不是“数据不需要备份”的依据。外部系统的数据由其负责方保护，但其证据和恢复点仍须纳入本次计划。

## 3. 一致性与执行流程

独立备份和变更前备份复用同一能力及排他协议。适配器固定版本，声明数据归属、备份/恢复依赖、格式、版本限制、冻结方法、健康检查、恢复粒度和验证方式。平台编排保护范围，不增加第二套 Helm release 安装排序或 values 合并器。

1. **计划与预检**：核对安装身份、来源版本、真实数据位置、外部依赖、保护范围、密钥可用性、容量及离线工具。指定本次 RPO/RTO 和停机预算，未配置则不能默认满足。
2. **锁与冻结**：锁定本次操作及关联的共享状态；停止相关业务写入者、CronJob、worker、迁移任务等并排空或记录在途任务。对 PG、对象和文件建立共同静止窗口或经验证的一致性协议；PG 全量导出本身不保证跨库/对象的一致时刻。
3. **生成备份集**：唯一 backupId，按数据归属去重。记录各项恢复点、版本、密文对象摘要和冻结状态；所有必需项完成后才原子提交成功标记。中断产生的部分结果不能成为可用恢复集。
4. **独立保存与校验**：至少一份不在本次修改/清理范围及源数据卷上的加密副本。从最终落点实际取回，验证完整性、解密和格式；涉及不可逆迁移的关键数据用本次备份实际隔离恢复。声明主机/集群灾备时还须跨相应故障域。
5. **执行或解除冻结**：升级前再次检查冻结、备份和计划绑定；独立备份完成后按持久记录恢复原运行状态。若重新开放写入，原备份不能直接作为随后迁移的零丢失恢复点，须重备或按已验证方案追平。
6. **失败处理**：持久化 freeze/thaw 与进程/命令状态；不能因管理机失联盲目解除只读，也不能无限期静默停服。展示需人工处理的具体服务、责任人与恢复指引。业务变更开始前失败，应在确认无旧命令运行后安全恢复原业务。

外部支付、邮件、Webhook、Git 推送、任务执行等效果不会随本地恢复撤销。冻结须覆盖入口、后台和外部回调，记录恢复后的重试/去重/补偿策略；缺少可验证策略时禁止把“恢复数据”描述为完整业务回退。

## 4. 保存、安全与容量

- 备份使用 age 等已选定的加密工具；缺公钥或工具时失败。私钥独立离线保管，不放入集群、备份集、浏览器或日志，也不通过命令行参数传递；向导只接收验证结果及公钥指纹，checkpoint 只保存引用和摘要。通过本地受控解密挑战及实际对象验证证明可用；保留适用旧备份的旧密钥，轮换不能使已有恢复点失效。
- 解密密钥、取回凭据、工具和入口不能只保存在待恢复的 PG/S3/Keycloak 中。准备离线恢复资料与受控应急访问；没有集群 API、原身份服务或原制品服务时也应能取得所声明的恢复资料。
- 备份账户与生产写入账户分离；声明抵御误删或受损管理员时，需独立权限/不可变或离线副本及验证。密文摘要只证明与已记录值一致，还须有受保护的清单/来源，防止数据与摘要一起被替换。
- 优先流式加密；旧脚本的明文暂存须逐项审计，使用受限临时存储、0600 权限并处理进程中断清理。备份读取和恢复执行按最小权限，敏感元数据也加密。
- 规模按“压缩数据库 + 必需对象/文件 + 无可用替代副本的制品 + 配置”实测估算，首版不假设增量/去重收益。分别计算最终备份、取回/解密暂存、新恢复卷、迁移期间新旧卷共存及快照写时复制增长的峰值容量；恢复吞吐与解密/导入/重建时间计入 RTO。
- 每个策略声明保留份数/期限、故障域与责任人。首版不自动清理；任务引用的恢复集固定保留，旧数据不能在切换验收前删除。将来支持增量、去重或自动清理时，必须验证整个依赖链、密钥保留及垃圾回收不破坏被引用恢复点。

## 5. 恢复协议与验证等级

备份清单记录：schema/backupId、安装与集群身份/generation、planId 及所属操作/阶段、来源发行及逐组件制品/schema/配置摘要、实际拓扑和数据映射、保护/排除范围、各数据恢复点、一致性方法、格式/工具版本、对象位置/大小/密文摘要、密钥指纹、依赖及恢复步骤、实际验证证据、RPO/RTO 目标和保留要求。非敏感索引与敏感清单分离，禁止只保存“旧 bundle 路径”。同一备份仅在新鲜度、身份、覆盖及规则匹配均有效时才可被后续计划显式引用，不能按版本号自动复用。

| 等级 | 能证明什么 | 放行规则 |
|---|---|---|
| 已生成 | 必需产物已输出 | 不能作为升级放行依据 |
| 完整性已校验 | 最终落点实际取回、解密/格式/身份/覆盖一致 | 所有升级必需，但不能标为“恢复已验证” |
| 隔离恢复已验证 | 按固定程序恢复到隔离目标，业务/身份/引用及源未受影响均通过 | 每个发布允许跨度必需；本次不可逆迁移按第 3 节额外验本次备份 |
| 灾备恢复已验证 | 声明故障域丢失后，在独立目标完成恢复并达到实测 RPO/RTO | 只有通过此等级才能声称覆盖该故障域；不能由应用隔离演练推导 |

生产恢复是显式独立操作，不由升级失败自动触发。首版集成已验收的隔离恢复适配器，生产原地恢复按固定 RUNBOOK 人工执行。恢复流程：

1. 选择恢复集和目标，展示将丢失哪些恢复点之后的写入、会影响哪些共享消费者；确认恢复方法在目标版本/拓扑上适用。
2. 隔离新旧目标，阻止双方同时接受写入；冻结生产并保存当前失败现场。演练环境默认禁外发、停用 CronJob/worker/Webhook，不允许复制生产凭据后直接联网启动。
3. 先准备离线工具、独立备份取回和密钥，再按恢复依赖建立必要网络/存储/数据服务，恢复原身份、配置与业务状态，最后启动应用。依赖顺序必须能处理“备份在 S3，而 S3 也要恢复”的循环。
4. 原集群恢复与新集群重建采用不同协议。新集群 UID/PV 句柄等会变化，须经过单独授权和映射，不能放宽原安装 resume 校验；CRD/控制器/CSI 就绪前不能直接盲目导入全部对象。
5. 验证数据、授权、解密、Git refs/LFS、对象引用、实际读写和端到端身份；再切换 DNS/LB/客户端入口，验证后恢复后台任务。恢复旧凭据/数据库可能使已撤销 token 或会话重新有效，需显式撤销/轮换策略及审计。
6. 记录实际 RPO/RTO、恢复来源与新的安装 generation，撤销旧任务/锁的执行资格，避免旧升级进程再次覆盖恢复结果。旧实例保留只读，确认无双写后再按独立流程退役。

## 6. 存储类与 K3s 配置变更的专门约束

| 变更 | 影响与必须验证的内容 |
|---|---|
| 修改默认 StorageClass | 已绑定卷不自动搬迁；检查新建 PVC 的实际落点，避免同一应用的新旧卷意外混用后端 |
| 迁移已有 PVC/访问模式 | 按支持的方法创建目标卷、复制/恢复、切换并保留旧卷；不得以强删 PVC 代替迁移。验证 RWO/RWX、UID/GID/权限、容量/配额、重启与跨节点调度 |
| 切换 CSI/后端/副本参数 | 验证绑定/挂载、拓扑、卷扩容和快照恢复兼容性；存储快照不假设能跨驱动恢复。实测 PG fsync/延迟、S3/Git 吞吐和应用响应，不能仅检查 Pod Ready |
| K3s 二进制升级 | 固定版本与允许跨度、逐节点执行并验证 API/组件兼容；保护配置和 datastore/token，回退方法单独验收，不能只替换旧二进制 |
| 注册表/CA/OIDC/入口配置 | 现有 Pod 可继续运行不代表重启可用；验证新建 Pod 拉取镜像、TLS、管理员及业务登录、回调与外部访问 |
| 节点/网络/DNS/CIDR/CNI/MTU | 检查 PV 节点绑定、调度、服务发现、跨节点流量及 NetworkPolicy；集群关键参数须一致。结构性变更按迁移/重建立项，不当作普通 values 更新 |

本节定义未来能力的保护要求，不改变升级方案首版对基础组件和存储的冻结限制。

## 7. 验收与实施前待定项

最低新增验收：按操作类型验证受影响依赖的完整保护；共享 PG 单应用恢复不影响其他库；备份对象损坏/缺片/错密钥拒绝；源 S3/API/身份服务不可用仍可独立取回；冻结/解冻各边界崩溃；真实 PG+S3+Git 一致性；工作台唯一文件保护；新存储重调度及性能；断网恢复旧工具/制品；恢复后会话、任务去重与旧进程隔离；声明灾备时实际模拟对应故障域丢失。

通用机制验收还须覆盖：相同发布包在不同版本/拓扑/组件选择的现场生成不同保护计划，构建不依赖现场信息；未知组件状态阻断；未更新的数据服务因消费者迁移被纳入；跨集群误用备份被拒绝；各阶段恢复点不混用；扩容后应用恢复不自动撤销扩容；新集群恢复只能通过显式身份映射；外网联网证据不能替代内网断网证据。

开发前须固定：首批支持组件与操作类型、恢复粒度、RPO/RTO 和容量预算、备份落点/保留责任、恢复适配器格式、外部系统边界及补偿策略、生产恢复权限、锁/fencing 与新集群身份映射方案。未决项影响的能力不发布；不通过放宽原规格或降低断言掩盖备份缺口。
