# 首批交付：契约与现场快照只读规划

设计基线：PR #21 `f4df37d` 的升级、分层备份两份方案。配套 chentu 验证基线：`76e08f8`。本批冻结范围是阶段 1 的版本化契约与阶段 2 的只读规划部分，不将整个阶段 1/2 或后续执行能力标为完成。

## 已交付

- chentu 发布清单新增生命周期契约，发布输入不接收现场安装、观测、意图或备份落点。默认未知 schema/空允许列表；冻结验收证据核验器尚未实现，因此禁止发布非空允许跨度或 verified 适配器，无法手填摘要放行。
- 安装记录、实际状态快照、组件迁移/数据保护及备份引用的严格 v1 模型；安装记录验证命令明确输出 liveVerified=false。
- 原生只读规划 CLI，绑定集群/安装/generation、来源/目标制品、配置、观测与意图，计算组件差异、迁移前提、共享数据去重、保护/冻结范围与恢复边界。
- 同一包可为不同来源版本、拓扑和组件选择生成不同计划；包内额外组件不自动安装，未知状态、来源漂移、缺证据或缺适配器明确阻断。
- 内网 3 server 加 5 agent 拆为扩容、基线提交、应用阶段；要求独立验收、扩容后重新观测及新鲜应用备份。应用恢复保留已验收节点，拒绝扩容前基线及跨集群备份。
- 所有执行入口保持阻断；带生命周期意图的向导请求不能落入首装。纯规划不调用 kubectl/Helm/Ansible/备份脚本。

下一步先完成可信只读采集、首装安装记录持久化及旧记录迁移/漂移诊断。当前输入由文件提供，只校验快照内部一致性，不能证明现场实时状态。

随后分别实现冻结证据核验、真实容量/RPO/RTO估算、备份与隔离恢复适配器、集群锁/fencing、冻结/解冻和执行任务对账。原生 multi-k3s 扩容以及各版本应用升级须另有真实与断网验收证据。
